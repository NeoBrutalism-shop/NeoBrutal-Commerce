# v1.1 System + foundation variant evidence

This report extends the certified v1.1 component variant-evidence lineage with the sixth source-audited batch. Commerce remains frozen at v1.0.0: this work does not add component IDs, normalized models, canonical actions, canonical states, semantic tokens, routes, provider semantics, or package exports.

## Combined status

The certified Account stage remains **38 / 47** variant-complete components and **100** authoritative variants. The System + foundation extension promotes exactly four additional components and 17 existing showcase labels:

- **42 / 47 components** variant-complete; **5 / 47** remain partial.
- **117 authoritative variants** total.
- Proof split: **67 rendered**, **42 canonical-state-backed**, **4 responsive-backed**, **2 interaction-backed**, and **2 action-backed**.
- The sixth batch is `system-foundation` and preserves the existing proof-kind contract.

## Promoted System + foundation components

- `component-contract`: `model`, `action`, and `state` are rendered from the existing explorer anatomy using frozen exemplars `ProductView`, `cart.add`, and `ready`.
- `tokens`: `semantic colors`, `depth`, and `press` render existing `src/tokens.css` authority, including `--nbc-depth: 6px`, `--nbc-press-hover: 3px`, and `--nbc-press-active: 6px`.
- `system-states`: `empty`, `loading`, `error`, `offline`, `permission`, and `unsupported` reuse the exact canonical `SystemState` entries and live state matrix.
- `ownership-lifecycle`: `active`, `grace`, `expired`, `cancelled`, and `refunded` render the frozen `OwnershipState` taxonomy while explicitly keeping license, entitlement, subscription, seat, activation, and transfer records conceptually separate.

## Exact residual partial set

Five components deliberately remain partial after this batch:

- `invoice-details`: live input anatomy and a frozen `InvoiceDetails` contract exist, but it is outside the certified 43-component implementation-evidence set and needs a dedicated residual audit before promotion.
- `purchase-history-row`: showcase `paid order` still conflicts with frozen successful `OrderStatus=complete`.
- `invoice-history`: showcase `open` is still not a frozen `InvoiceStatus` (`paid | refunded | void`).
- `activation-row`: showcase `removable` still lacks a canonical activation removal/deactivation action.
- `seat-assignment`: showcase `capacity reached` still lacks capacity in the component's frozen model/action-result authority.

The System extension fails CI if any of these five become variant-complete without a deliberate evidence change.

## Evidence files and runtime

`storefront/component-variant-evidence-system.json` is the sixth variant-evidence shard. `storefront/component-demo-depth-system.json` records the bounded four-component `All variants` promotion. `component-depth-system-extension.js` runs only after the Account depth stage and verifies the intermediate 38 complete / 9 partial state before advancing to 42 complete / 5 partial.

The runtime continues to use the existing five proof kinds only. Browser QA covers all 17 System variants, exact canonical state reuse, keyboard/tactile behavior, dark/narrow containment, and targeted WCAG A/AA Axe checks.

## Frozen boundaries

This batch does not reinterpret explorer examples as new runtime contracts. `component-contract` teaches existing model/action/state boundaries; `tokens` exposes existing CSS variables; `system-states` references existing canonical state authority; and `ownership-lifecycle` uses existing normalized ownership status vocabulary without claiming provider-returned dates, prices, capacity, billing outcomes, entitlement outcomes, or ownership completion.
